# Architecture

```
            ┌──────────────────────────── browser / OS webview ───────────────────────────┐
 keyboard → │ InputManager ─► PlayerInput ─► Session ─► World (sim, 60 Hz fixed) ─► events │
 gamepad    │                 (+ UI commands)   │            │                        │    │
 mouse      │                                   │            ▼                        ▼    │
            │                                   │   Renderer (Pixi v8)        Audio (WebAudio)
            │                                   │   UI / HUD (Pixi, pixel font)              │
            │                                   ▼                                            │
            │                         net: Transport (WebRTC / WebSocket / loopback)         │
            └───────────────────────────────────┼────────────────────────────────────────────┘
                                                ▼
                       other players (P2P) · Cloudflare signaling/relay · optional Bun server
```

## Layers and directories

| Dir | Purpose | Rules |
|---|---|---|
| `src/engine/` | Generic utilities: seeded RNG, math, input, (later) spatial hash, binary codec | No game knowledge |
| `src/content/` | Game data: items, recipes, enemies, bosses, biomes, resources, races, hats, companions, skills, npcs | Pure data + `validateContent()` |
| `src/sim/` | Deterministic simulation (the game rules) | Pure TS, no DOM, see CLAUDE.md rule 1 |
| `src/sim/gen/` | Procedural level generation per biome, towns, boss arenas, traversability validator | Pure function of `LevelRequest` |
| `src/net/` | Netcode: protocol, codec, host, client prediction, transports | No DOM except transport impls |
| `src/render/` | Pixi renderer: tile chunks, entities, procedural sprites, lighting, glow, particles, camera | Reads sim state, never writes it |
| `src/render/sprites/` | Procedural pixel-art generator (code-drawn sprites → texture atlas) | Deterministic per sprite key |
| `src/ui/` | HUD, inventory/crafting, menus, pixel font | Emits `PlayerCommand`s, never mutates sim |
| `src/audio/` | Procedural SFX synth + chiptune music | Reacts to `GameEvent`s |
| `src/game/` | App flow: boot, menus ↔ run, sessions, fixed loop, settings, meta-progression save | Glue |
| `server/` | Signaling/relay (Cloudflare Worker + Durable Object) and optional dedicated Bun server | Reuses `src/sim` + `src/net` |
| `desktop/` | Bun/Deno webview shell embedding `dist-single/index.html` | |

## Simulation

- `World.step(inputs)` advances exactly one tick (1/60 s). Systems run in the fixed order in
  `src/sim/systems.ts`; the order is part of the determinism contract.
- State = `world.level.grid` (TileGrid typed arrays) + `world.entities` (plain objects) +
  `world.players` (plain objects) + `world.rng` state + `world.run`. Everything else is derived.
- Entities: one flat `Entity` shape with optional components (`ai`, `projectile`, `pickup`, `resource`,
  `swing`, `light`…). Systems filter by `kind` / component presence.
- Presentation-only `GameEvent`s are emitted into `world.events` each tick (sfx, particles,
  damage numbers, shake, messages). Dropping them never affects the sim.
- UI actions travel as `PlayerCommand`s inside `PlayerInput.commands` (craft, swap, equip, buy…).
- `src/sim/index.ts#createRun(seed, setups)` builds a world; `LevelRequest` → `generateLevel()` is
  pure, so clients regenerate levels locally from the request instead of downloading tiles.

### Tick pipeline (src/sim/systems.ts)
`freeze → commands → playerControl → playerAction → ai → physics → melee → projectiles →
contactDamage → hazards → status → pickups → meters → progression → exit → inputLatch`

## Rendering

- Native view ≈ 320×180 px, scaled by the largest integer that fits (4× at 720p, 6× at 1080p).
  Nearest-neighbour sampling; camera at sub-native-pixel precision for smooth scrolling.
- Layers (back → front): sky haze → parallax → back-wall tiles → background resources (trees) →
  props → entities → foreground tiles → particles → **lightmap (multiply)** → **glow (additive)** →
  world-space UI (names, damage numbers) → HUD.
- The look is defined by darkness: ambient ≈ 0.1, players carry warm radial lights, emissive things
  (lava, crystals, projectiles, fireflies) glow. See `docs/research/screenshot-analysis.md`.
- Tiles are drawn per 32×32-tile chunk into canvases, rebuilt only when `chunkVersion` changes.
- Sprites are generated by code at startup into atlases (no image assets required).

## Multiplayer (high-performance, browser + desktop)

**Topology: host-authoritative listen server, P2P transport.** One peer (a player's browser tab
or desktop app — or an optional headless Bun server running the same code) owns the authoritative
`World`. Other peers send inputs and receive snapshots. Up to 4 players.

| Concern | Approach |
|---|---|
| Transport | `Transport` interface with channels `unreliable` (unordered, no retransmit) and `reliable` (ordered). Implementations: **WebRTC DataChannels** (browser, WebView2, WKWebView), **WebSocket** (relay fallback / dedicated server), **Loopback** (tests; simulates latency, jitter, loss). Linux WebKitGTK may lack WebRTC → desktop shell can provide native networking or use the relay. |
| Signaling / lobbies | Cloudflare Worker + Durable Object per room code (SDP/ICE exchange, lobby list, WebSocket relay fallback). Free STUN (Google/Cloudflare), TURN for strict NATs. |
| Client → host | Every tick: input packet with the last ~8 inputs (redundancy over the unreliable channel), tagged with tick numbers. UI `PlayerCommand`s go on the reliable channel. Host keeps a small jitter buffer per client and repeats the last input when one is missing. |
| Host → client | Snapshots at 30 Hz, **delta-compressed against the last snapshot the client acked**, binary-encoded (quantised positions, bitfield flags, varints), filtered by **interest area** around each client's player. Owner-only private state (inventory, stats) sent reliably on change. Tile edits as a reliable ordered delta log. Levels are regenerated locally from the `LevelRequest` (seeded), never transferred. |
| Local player | **Client-side prediction + reconciliation**: run controller + physics for the own player every tick; on snapshot, rewind to the server state and replay unacked inputs. Own attack animations/SFX are predicted; damage is confirmed by the host. |
| Remote entities | **Snapshot interpolation** with an adaptive ~2–3 snapshot buffer (≈ 70–100 ms). Extrapolate briefly on loss. |
| Fairness | Optional lag compensation: host rewinds enemy hitboxes by the client's interpolation delay when resolving that client's melee/projectile hits. |
| Budgets | Sim ≤ 2 ms/tick (4 players, ~300 entities); snapshot ≤ ~1 KB typical (MTU-safe, fragmented above 1.1 KB); input packet < 100 B. |
| Determinism | The sim is deterministic anyway (seeded RNG, fixed step), which keeps prediction accurate, enables replays/tests, and leaves the door open for rollback later. Cross-engine float differences don't matter because the host is authoritative. |

## Desktop packaging (later phase)

`bun run build:single` → `dist-single/index.html` (everything inlined). A Bun (`webview-bun`) or Deno
(`@webview/webview`) shell loads that HTML into the OS webview (WebView2 / WKWebView / WebKitGTK) and
is compiled to a single executable. The shell's native side can host networking/saves if a webview
lacks a feature.
