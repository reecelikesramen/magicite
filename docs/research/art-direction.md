# Shardfall art direction (procedural pixel art, HUD, audio)

The actionable visual and audio spec for Shardfall's **code-generated** art. It is distilled from the
original game's look (screenshots, trailer, decompiled camera/HUD code; see `magicite-reference.md`) and
written for our biome, enemy and item ids from `docs/design/gdd.md`.

- **Authority.** `docs/research/screenshot-analysis.md` is the ground truth for the original's look. Where
  this file disagrees with it about the *original*, the screenshot file wins. Everything else here is our
  design choice, made to evoke the original without copying it.
- **Originality (CLAUDE.md rule 6).** Match the *style* (chibi proportions, darkness, glow, palettes), never
  the original's sprites, logo, UI glyphs or names. All art is generated by code from sprite keys.
- **Tags.** [SS] screenshots, [V] trailer/store frames, [C] original code, [G] our design decision.

## 1. Resolution, scale and camera

| Item | Spec | Why |
|---|---|---|
| Native view | **320×180** (`VIEW_W`/`VIEW_H` in `src/render/renderer.ts`) | The original's release build shows ≈320×180 at 720p [SS] (≈341×192 in code [C]) |
| Upscale | Largest integer that fits: 4× at 1280×720, 6× at 1920×1080; letterbox the rest with `#000` | The original scaled non-integer; we stay pixel-perfect [G] |
| Sampling | Nearest-neighbour for world sprites, tiles and HUD | Crisp pixels |
| Exceptions | **Light map and bloom are smooth** (linear filtering at output resolution) | "Falloff is a smooth gradient, not pixelated" [SS] |
| Tile | **8×8 px** (`TILE = 8`); view ≈ 40×22.5 tiles | [SS] |
| Camera position | Sub-native-pixel (smooth scrolling); sprites snapped to native pixels relative to the camera | [SS] smooth scrolling |
| Follow | `cam += (target − cam) × (1 − exp(−2·dt))` (≈0.5 s time constant) | Original: `lerp(pos, target, dt·2)` [C] |
| Look-ahead | Target = player + **0.25** × (cursor − player), clamped to ±48 px x, ±28 px y; gamepad uses aim stick × 40 px | Original leaned **50%** toward the cursor [C]; halved to avoid nausea [G] |
| Menus open | Lean = 0 (centre on the player) | [C] |
| Shake | On player melee hit: 1 px for 6 ticks; heavy weapon or boss slam: 2 px for 10 ticks; decays linearly; global "screen shake" option | Original shook on melee hits only [C] |
| Hit-stop | 2–4 ticks on melee hits (extension) | Fixes "melee feels weak" [G] |
| Co-op | Every client has its own camera at the same zoom; no shared screen online. Local co-op (extension): shared camera that frames all players; above a spread of 280×150 px, split vertically | [C][V], GDD §11 |

## 2. Tiles and terrain

### 2.1 Layers per tile

1. **Body** (solid ground/rock): lumpy organic **cobble blobs** 3–6 px across, 2–3 shades, separated by 1 px
   darker gaps. Never clean grid bricks, except in brick biomes (`ossuary`). [SS][V]
2. **Top fringe** on every exposed top face, 1–3 px tall, poking **1–2 px above** the tile edge: grass tufts
   with a crenellated top, snow caps with 1–2 px notches, magenta crystal lumps, lava crust. A darker,
   checker-dithered band sits under the fringe. The fringe also grows on exposed **side** faces (shorter,
   1–2 px) and as a ragged lip under overhangs. [SS][V]
3. **Back wall** behind all playable space: the same blob texture at ≈30% brightness (palette `wall`),
   visible only within the light halo. [SS][V]
4. **Far background**: flat `sky` colour, optionally with haze (§9).

### 2.2 Generation rules (deterministic per tile)

- Seed every tile's texture from `hash(biome, tx, ty)`; never from `Math.random`.
- Body: stamp 3–6 blobs per tile from a small blob library (circle-ish 3×3 to 6×5 shapes), shade each blob
  with ramp index 1–2 and a 1 px highlight (index 3) on its upper-left, gaps index 0. Let blobs cross tile
  edges using the neighbour's hash so seams vanish.
- Fringe: per column x, height = 1 + (hash(x) mod 3); lit tips use the brightest ramp entry. Crenellation:
  every 3rd column has a 1 px gap.
- Edges: auto-tile on the 4-neighbour mask. Exposed bottoms get a 1 px dark ragged lip, exposed sides 1 px.
- Ore veins and gem pockets are **separate resource props**, not tile art (original used nodes [C]).
- Diggable terrain (GDD extension): breaking a tile spawns 4–6 1-px debris particles in the body ramp.

## 4. Outlines, shading and colour rules

- **Outline**: 1 px, colour `#1e1a0c` (warm near-black), on characters, creatures, items, icons, chests and
  UI badges. **Not** on terrain, trees, foliage, particles or light effects. [V]
- Sprites use **3–6 colours**: flat fill + one highlight + one shade, with light dithering only on large
  creatures. [V]
- Light comes from **above-front**: highlight the top and upper-left 1 px edge, shade the bottom rows.
- Eyes are 1 px dots (2 px for large creatures). **Glowing eyes** (`#faf879`, `#ff4040`, `#40ffff`) mark
  hostiles that would otherwise vanish in the dark.
- Hostile vs friendly: hostile projectiles carry a **1 px darker ring** and pulse at 6 Hz; friendly projectiles
  have no ring. Scourge-style corrupted creatures (our Blight) are **magenta/purple + black with white
  teeth/eyes**. Passive animals are pastel. [V][G]
- Never use pure `#000000` inside sprites (it disappears into the dark world); use the outline colour.

## 5. Lighting model (the look)

The world is **near-black**; only light reveals terrain. This is the single most important trait. [SS]

### 5.1 Composite

```
world  = tiles + props + entities                     (albedo, native res)
light  = ambient(biome) + Σ lights                    (light RT, additive, smooth)
lit    = world × light   (per attenuation class, see 5.3)
final  = lit + glow(emissive) + bloom(threshold) ; then world-space UI ; then HUD (unlit)
```

Light falloff (smooth, unbanded):

```
L(d) = colour × intensity × max(0, 1 − (d / R)²) ^ 1.5
```

Allow `intensity > 1` so that lit fringes **clip toward yellow-white** (grass tips `#e3ff45`, snow `#f5f5f3`,
crystal crust `#ff50c0`), exactly as the original over-exposes near the player. [SS][V][C]

### 5.2 Light sources

| Source | Colour | Radius (tiles) | Intensity | Behaviour |
|---|---|---|---|---|
| Player (each player) | `#ffc070` | 5 | 1.5 | Steady; drawn at the chest. The original was 4–6 tiles at 320×180 [SS] |
| Downed player | `#ff8060` | 3 | 0.8 | Slow pulse 0.6–0.8, 1 Hz |
| Torch / lantern / campfire | `#ff9a40` | 3.5 | 1.2 | Flicker: × (0.85 + 0.15·noise(t)), resampled every 6 ticks |
| Lava surface | `#ff6010` | 2.5 | 1.0 | Along lava rows; slow shimmer |
| Fire vent / burst | `#ff8020` | 2 | 1.3 | Only while active |
| Purple crystal | `#a060ff` | 3 | 1.0 | Pulse 0.8–1.0 over 3 s |
| Cyan crystal / ice | `#60e0ff` | 2.5 | 0.9 | Pulse 0.85–1.0 over 4 s |
| Firefly / glow bug | `#9cff3a` | 1 | 0.6 | Moves with the bug |
| Slime (green) | `#88ff80` | 0.75 | 0.5 | Emissive body [SS] |
| Portal | destination colour (§7.4) | 3 | 1.0 | Swirl particles |
| Fireball | `#ff9040` | 2 | 1.2 | |
| Magic orb | `#40ffff` | 1.5 | 1.0 | |

| Blight veins (Lair) | `#ff2080` | 2 | 0.7 | Heartbeat pulse 0.5–1.0 at 1.2 Hz |

### 5.3 Attenuation classes

The screenshots show near-black terrain; the trailer shows creatures and trees readable everywhere. We
combine both by giving each layer a **minimum light floor**:

| Class | Floor (fraction of full brightness) | Members |
|---|---|---|
| Back wall | 0 (ambient only) | Back-wall tiles |
| Terrain body | `ambientLevel` (0.08–0.16 per biome) | Solid tiles |
| Terrain fringe | 0.18 | Top/side fringe pixels, so level silhouettes read across the screen [V] |
| Background props | 0.30 | Trees, plants, houses, decor |
| Creatures and players | 0.60 | Enemies, NPCs, critters, players, held items |
| Emissive | 1.0 (+ glow) | Slimes, fireflies, crystals, lava, projectiles, portal interior, eyes, UI-in-world |

### 5.4 Bloom

Threshold ≈0.7 luminance, radius 2–4 native px, add 30–50%. `pixi-filters` `AdvancedBloomFilter`
(threshold 0.7, bloomScale 0.4, blur 3) on the emissive layer only. Turn bloom off in the Canvas fallback
renderer (see `tech-stack.md`).

## 9. Parallax and background

The original used a single dark back-wall quad per biome and **no parallax** [C]. We allow subtle depth
without breaking the darkness:

| Layer | Scroll factor (x / y) | Content | Max luminance |
|---|---|---|---|
| Sky haze | 0 / 0 | Flat `sky`, vertical gradient toward `ambient` haze (strong in `fen`) | 8% |
| Far | 0.15 / 0.08 | Distant cave silhouettes, stalactites; a few twinkling emissive dots (crystals, stars in `crater`) | 6% (dots exempt) |
| Mid (optional) | 0.4 / 0.2 | Large rock pillars or tree silhouettes, 1 shade above `wall[0]` | 8% |
| Back wall | 1 / 1 | Back-wall tiles, lit by lights only | — |

Generate far/mid layers per biome from the level seed (deterministic), as 512-px-wide tileable strips.

## 13. Audio and music direction

### 13.1 Music system

- One looping track per biome, one per town flavour (2–3 variants), one boss theme per giant monster tier
  (the original shared a single boss track [C]; we can afford 2), a **Blight-invasion** theme, title, victory,
  game over.
- The original used **hard cuts** with a 0.5 s gap [C]. We fade out over 0.4 s, wait 0.2 s, start the next
  track; boss and invasion themes start with a one-bar sting.

  triangle bass, a noise drum channel, plus one soft pad for caves). Patterns are data in `src/audio/`;
  music is chosen from `levelEnter` events (`isTown`, `isBoss`, biome id).

### 13.2 Sound effects (zzfx)

Every SFX is a zzfx parameter array keyed by `GameEvent` (`sfx` ids, `pickup`, `craft`, `levelUp`, `downed`
…). Spatialise by distance to the listener (volume and stereo pan, cut off beyond ≈1.5 screens).
Parameter order (zzfx 1.4): `[volume, randomness, frequency, attack, sustain, release, shape, shapeCurve,
slide, deltaSlide, pitchJump, pitchJumpTime, repeatTime, noise, modulation, bitCrush, delay, sustainVolume,
decay, tremolo, filter]`; shape 0 sine, 1 triangle, 2 saw, 3 tan, 4 noise, 5 square (duty = shapeCurve).
